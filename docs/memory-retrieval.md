# 记忆选择与本地语义检索

原始经历、Soul 文件、版本和验证状态保持原样。选择只作用于单次请求，不按时间删除，也不把召回次数当作经验已验证的依据。

- `feiyu_experience_recall` 和 `character-cli.mjs` 使用异步本地语义检索与关键词联合排序。搜索所有已导入经历；源适配器每种来源的导入范围仍需单独核实。
- 热层在 DSH `system-prompt/assemble` 中处理 `soul:memory` / `soul:recall`，按当前用户问题选择完整段落并去重。`soul:persona` 不参与删减。
- 传输层仅投影显式记忆段和已知召回工具的重复片段，不改用户输入、工具调用 ID、推理前缀或持久会话。预算不足时舍弃可选记忆，不截短人设来腾位置。
- 召回包含来源 ID、哈希、原文偏移、截断标记和回执。新回执另存片段起点，旧回执默认从 0 开始。相似度不是事实置信度。

## 启用语义检索

独立 Python 环境安装 `fastembed==0.7.4`。使用 CPU 模型 `BAAI/bge-small-zh-v1.5`，不上传原文、不需要云端向量数据库。首次准备模型需要联网下载。

在 `$DSH_HOME/feiyu-runtime/memory-retrieval.json` 设置：

```json
{"enabled":true,"python":"你的 Python 绝对路径","modelCache":"模型缓存绝对路径"}
```

构建可重建索引：

```text
python lib/memory_semantic.py build <DSH_HOME/feiyu-runtime>
```

索引是独立的 `memory-vectors.sqlite3`；原库只读。查询离线加载模型，最多等待 15 秒，失败明确退回关键词并报告状态。查询会顺便补充最多 4 条不超过 9,600 字符的新记录；较长新记录仍能关键词检索，需再次运行 build 完整建立向量索引。没有新增定时任务。构建逐条事务提交，可从断点继续。

## 预算与限制

使用保守 UTF-8 字节估算，不宣称是 provider 精确 Token 数。当前经历投影预算 9,000 字节，包含附属创作/关系后的响应目标 16,000 字节；热层上限 12,000 字节，传输时受请求剩余预算约束。DSH 自己的上下文管理继续负责非记忆内容。陪看则在原有 `pack_messages` 总预算内进行相关性选择和去重，不另外叠加记忆额度。

分块与向量相似度仍可能返回上下文不足或只是主题相近的片段，需按来源进一步核对。未索引新记录、原始来源尚未导入、语义模型不可用都不能解释为“没有发生过”。工作台的记录列表不使用这套请求裁剪。
